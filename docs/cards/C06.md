## Design evidence

The pinned source at `/private/tmp/proxima-c02-audit` is commit
`875e56d366083f6fea4128626eb546a6269931db`. Its
`proxima-primitives/src/pipe/primitives.rs` root `Pipe::call` takes one `In`
and returns a future of `Result<Out, Err>`; `proxima-primitives/src/pipe/ext.rs`
provides composition but no function-to-pipe adapter. Therefore the minimal
`LifecyclePipe` zero-sized type is justified as the required `Self` for the
foreign trait impl; it contains no state. Its concrete types are:

- `In = (State, Event)`
- `Out = (State, Effect)`
- `Err = core::convert::Infallible`

`call` delegates to the already-tested sans-IO `transition` function. The
returned future is immediately ready and does not perform I/O or allocate.
Proxima is pinned in Cargo by the same immutable revision and default features
are disabled so this base pipe does not pull Proxima's std/alloc feature tier.

## Postmortem

Reading the pinned root trait and extension API showed there is no function
adapter to reuse; the zero-sized implementing type is required for the trait
impl and carries no state. Keep each future card tied to its pinned source and
record its associated types rather than using broad labels. Since `Err` is
`Infallible`, compile-time shape and successful result assertions are the
available error evidence; there is no runtime error value to test.
