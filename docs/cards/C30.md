# C30 — Retain 0.8.0 native release wheels

## Goal

Make the existing native wheel matrix retain each successfully tested 0.8.0
wheel as a run artifact whose name ties it to the exact source SHA and platform.
This supplies immutable wheel inputs for C27 artifact assembly.

## Acceptance

- Add a post-test upload step to `.github/workflows/native-wheels.yml`.
- After the installed-wheel tests pass, run a cross-platform selector that
  asserts exactly one `vsh-0.8.0-*.whl`, writes that exact path to
  `GITHUB_OUTPUT`, and fails on zero or multiple matches.
- Each Linux/macOS/Windows job uploads only the selector output, named with
  `vsh-0.8.0`, `${{ github.sha }}`, and the platform; fail if the file is absent.
- Keep the step after the installed-wheel tests, so red tests cannot publish a
  release input artifact.
- Push one candidate commit and let the existing push-triggered matrix run;
  do not manually dispatch a duplicate workflow.
- Verify all three jobs are green with 4 installed-wheel tests each and that
  exactly one correctly tagged 0.8.0 wheel artifact is retained per platform,
  all artifacts tied to the candidate SHA. Verify downloaded artifact names, exactly one file per platform, and each wheel filename/tag.
- Obtain independent code↔card and tests↔card reviews, write/review postmortem,
  and promote the candidate worktree branch → local `main` → `origin/main`.

## Baseline evidence

At C30 start, `origin/main` is `4f0b6fac9e0a9687b851c6dbf3b85c7b9c786be6`.
`.github/workflows/native-wheels.yml` already builds and tests a 0.8.0 abi3
wheel on Linux, macOS, and Windows with four passing installed-wheel tests per
job, but it does not upload the wheel. `scripts/card_c24_matrix.py` builds into
`target/c24-wheels-*`. C27's initial scope review found that those exact tested
files could not otherwise be collected and tied to a promoted source revision.
