# C11 — guarded venv removal pipe

## Status and acceptance

Started 2026-10-14 16:26:21 UTC on `cards/c11-remove-venv-pipe`, based on
`512ecc4`. Estimate: 17 minutes.

- Accept validated `Config` and a dry-run flag through a Proxima sink pipe.
- Compose the C09 layout observer/validator before any removal; reject invalid
  or missing environments without deleting anything.
- Remove the venv and its configured vsh config file on a real run; dry-run
  preserves both.
- `cargo test -p vsh-core remove_venv` selects at least one test covering
  invalid, dry-run, and successful removal behavior.
- Independent code↔card and tests↔card reviews, postmortem, and promotion
  worktree → local `main` → `origin/main`.

## Design evidence

`RemoveVenvPipe` is one zero-sized Proxima type with `In=(Config, bool)`,
`Out=()`, `Err=conflaguration::Error`; the sink shape matches a filesystem
operation with no success payload. It reuses existing `Config` and C09 layout
pipes, adding no request/result struct. Validation occurs before filesystem
mutation, and dry-run returns after the same guard. Filesystem removal is an
explicit std boundary.

## Postmortem

Postmortem: The first test review found that proving the environment survived
an invalid-layout rejection did not prove its separate config file survived.
The revised test checks both paths for every guard, plus a missing environment
and a semantically invalid `Config` paired with an otherwise valid environment.
For future destructive pipes, assert every independently deleted path across
each early-return case. This card took 3 minutes against a 17-minute estimate.
