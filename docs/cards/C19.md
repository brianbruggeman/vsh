# C19 — Proxima telemetry wiring

## Acceptance

- Configure Proxima's process recorder and emit filter through CLI-owned,
  validated configuration pipes. `EmitConfig` is Proxima's conflaguration
  `Settings` value; resolution and installation both call `.validate()`.
- Instrument CLI action execution with Proxima spans and mark errors; report
  operational failures through Proxima's error macro.
- Prove a configured recorder captures a span and an error log, and prove an
  ambient emit with no default recorder remains a no-op. Drain records before
  process exit so errors are not stranded in recorder rings.
- `cargo test -p vsh-cli telemetry` has N>0 and exercises the actual
  `RunActionPipe` failure span; CLI/core regressions, fmt/diff,
  code↔card and tests↔card reviews, postmortem, and branch→main→origin landing.

## Design

The CLI resolves Proxima's existing `EmitConfig` from `EMIT_*` settings, then
passes it into recorder installation. The two setup pipes separate config
resolution from the recorder side effect. `DrainTelemetryPipe` makes the
process-exit flush explicit. `execute_action` is async and uses Proxima's
`#[instrument(err)]`; operational errors use `error!`. No additional config
struct or local logging facade was introduced.

## Postmortem

The first telemetry test run clarified that Proxima's `EmitConfig::validate()`
rejects bad levels before `compile()`; adjusted the test to assert the actual
boundary. The CLI smoke test's first root was too broad and scanned 1,150
directories, so subsequent smoke tests use a dedicated empty temp root. Review
found that Proxima's `Recorder::drain()` drains one batch only; the exit pipe
now loops until a pass returns zero. Tests initially covered a helper span
instead of the real action, so the integration test now invokes
`RunActionPipe` and checks its error status. Save focused gate output in the
worktree before requesting review so claims can be checked directly.
