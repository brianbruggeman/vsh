## Design evidence

`State`, `Event`, and `Effect` are the three domain vocabularies needed to make
the state transition and its requested effect explicit. They are `Copy` enums
with no owned payloads. `transition` returns a tuple instead of a result
wrapper because the wrapper would carry no extra invariant. The fallback
preserves state and returns `Rejected`; callers decide how to report that.
Ephemeral create and enter have distinct states so exit can request removal
without hidden flags or I/O in the FSM.

The test compares an independent expected-transition table against every one
of the 99 state/event combinations. It separately repeats the ephemeral
create→enter→exit→remove path 10,000 times. A failed ephemeral create or enter
requests cleanup while the `CleaningEphemeralFailure` state retains the failure
outcome; successful removal returns to `Failed`. The function body only matches
enums and returns enum/tuple values; it has no allocator-facing operation.
This is a structural allocation argument, not a benchmark or a measured
allocation count.

## Postmortem

The first review pass exposed two omissions: ephemeral operation failure did
not request cleanup, and the exhaustive loop only checked rejected pairs, so
most admitted transitions could regress unnoticed. Include failure cleanup in
ephemeral workflows and compare every state/event pair with an explicit oracle.
The corrected table covers all 99 pairs; the function remains structurally
allocation-free. Future review should distinguish that source-level property
from a measured allocation count.
