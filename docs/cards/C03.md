## Design evidence

- `conflaguration` is pinned at the crate release `2.0.0` with `derive` and
  `toml` features. The source API confirms `.env()` resolves settings but does
  not validate; the config path therefore calls `.validate().build()` explicitly.
- `#[derive(Settings)]` is generated by conflaguration. `Validate` is manual
  because its derive only cascades into nested/flattened values and cannot
  express the non-empty-name rule.
- The CLI ownership boundary is planned for C15: CLI resolves file/env/flags,
  validates, then passes this `Config` value into the Rust library. `from_value`
  is the validated fluent/library construction path.
- Guiding principles applied before design: §1 reuse conflaguration instead of
  making an env parser; §3 this host CLI uses std runtime settings, not a false
  no_std runtime-config claim; §4 one serializable public config and fluent/env
  path; §6 derive behavior was checked in conflaguration 2.0.0 source; §11 no
  state machine is needed for static config; §16 the validation test and exact
  count travel with the claim; §17 the test describes the resolved/invalid
  behavior; §18 no performance claims are made. Config is resolved once on the
  cold path, so its owned strings/paths do not enter the operation hot path.
