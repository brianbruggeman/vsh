# C33 — Include release documentation in the sdist

## Goal

Make the 0.8.0 source distribution contain its declared README, changelog, and
license, and validate the package inputs before producing a new native wheel
candidate.

## Acceptance

- Update PEP 621/Maturin metadata so README.rst and LICENSE are declared as
  project metadata files, and CHANGES.rst is explicitly included in the sdist.
  Use Maturin's documented `tool.maturin.include` format for sdist-only files.
  Ensure the README's guide link resolves to the published `docs/using-vsh.md`
  page from PyPI-rendered metadata.
- Build an sdist locally and require `PKG-INFO` version 0.8.0, README.rst,
  CHANGES.rst, and LICENSE. Compare its normalized members against the tracked
  release inputs; require zero missing and only explicitly allowed generated
  metadata (`PKG-INFO`) as an extra.
- Build and install the local native wheel; run the installed-wheel smoke tests
  with a nonzero count and verify package version remains 0.8.0.
- Commit and push one candidate. Use only the automatically triggered native
  matrix; require Linux/macOS/Windows each green with four installed-wheel
  tests and one retained wheel artifact tied to the new source SHA. Do not
  manually dispatch a duplicate. If the hosted queue threatens 20 minutes,
  split hosted artifact verification into a fresh card rather than waive it.
- Obtain independent code↔card and tests↔card reviews, write/review the
  postmortem, and promote the green commit worktree branch → local `main` →
  `origin/main`.

## Postmortem

The initial sdist probe exposed a documentation-file gap and a relative README
guide link that would not resolve from PyPI-rendered metadata. Declaring the
README and license as project metadata, including the changelog only in the
sdist, and using the published absolute guide URL made the archive complete
while README.rst and CHANGES.rst stay out of the wheel payload; README and LICENSE
are carried as package metadata. A one-off inventory script also first raised
`OSError: TarFile is closed`; the corrected check snapshots member names inside
the archive context before asserting. For later packaging cards, keep the
fixture inventory exact, build from the candidate source, capture archive members
while open, then validate rendered metadata and the installed wheel.
