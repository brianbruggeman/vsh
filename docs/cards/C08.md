## Design evidence

Two zero-sized pipe types are justified by the two different typed operations:
`LoadConfigPipe` transforms `PathBuf -> Config`, while `StoreConfigPipe` is a
sink `Config -> ()`. Both use `conflaguration::Error` for I/O, TOML parse,
and validation failures. `ConfigFile` action/result wrapper enums would add
indirection without carrying more information. Each pipe owns its designated
filesystem boundary and contains no loop, lock, or channel. The legacy format
is TOML stored with `.cfg`; direct `toml::from_str` avoids extension dispatch,
then legacy path repair strips exactly one complete outer quote pair and the
conflaguration value builder calls `.validate()` before returning the config.
Unmatched quotes in canonical path values are preserved. Store uses the same
validated builder path before creating directories or writing serialization.
The stale executable paths in the second fixture are preserved after quote
repair. C12 adds interpreter/shell discovery and evaluates stale-path fallback.

## Postmortem

Review concrete file format edge cases: strip only the legacy wrapper pattern,
and preserve canonical paths with one trailing quote. Exercise both sides of a
file API in tests: invalid loads and invalid stores, plus storing a repaired
legacy fixture itself. A new-config roundtrip alone cannot prove canonicalizing
legacy input. Let `tempfile` own test paths rather than reusing process-ID-only
names. TOML may choose single-quoted strings for values that contain quotes;
assert the semantic roundtrip and only the exact canonical text properties
needed for the format claim.
