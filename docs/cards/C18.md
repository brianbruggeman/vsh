## Design evidence

`PyVenv` is the ABI wrapper required to expose an environment through PyO3. It
holds the existing `Config`; it adds no duplicate Rust lifecycle state. Each
operation checks the existing SansIO lifecycle pipe and delegates effects to
the create, shell, layout, environment, or remove pipes. `from_config` carries
all fields from a validated `Config` into the wrapper.

## Postmortem

An initial test run skipped the real lifecycle case because a `slow` marker
was intercepted by an inherited pytest plugin. Removed the marker so the card
gate exercises create→enter→remove by default. The first Rust compile also
showed that the options wrapper correctly hides its inner field; added a
consuming accessor instead of widening field visibility. Review caught a
missing FSM step, dry-run state advancement, and loss of caller config fields;
the card now records each issue and uses lifecycle transitions plus
`from_config`. Keep shared PATH resolution in one core pipe so CLI and Python
callers use the same behavior. The first attempts at recording the Python gate
omitted pytest's final summary; using `-rA` produced named test evidence and an
explicit count. Early runner setup attempts failed because the temporary venv
path was stale and system Python lacked pytest; the successful gate
uses uv-provisioned pytest outside the checkout to ensure it imports the wheel.
