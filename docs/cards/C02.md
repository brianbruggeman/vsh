  it contains 23 `use_when` entries, each mapped below.
- Root API: `proxima-primitives/src/pipe/primitives.rs`, `Pipe` around line 91;
  `AndThen` around line 190. `Pipe::call` is an async one-step
  `In -> Result<Out, Err>`. `AndThen` feeds first `Out` to second `In`, and
  requires `Second::Err: From<First::Err>`. `PipeExt::and_then` is sugar over it
  (`proxima-primitives/src/pipe/ext.rs:45-57`).
- The four forms are the same trait: transform `In -> Out`, source `() -> Out`,
  sink `In -> ()`, observe `In -> In` (`primitives.rs` trait docs).
- Proxima’s `Pipe` is async, so effects belong at explicit pipe boundaries;
  decision logic can remain pure/sans-IO. No `Send` bound is imposed by the root
  trait (`primitives.rs:91-105`).

### Pinned-source discrepancies and constraints

- `filter` has two relevant surfaces. `PipeExt::filter` composes any
  input-aware `Pipe<In=T,Out=T,Err=E>` before the inner pipe, and the example
  uses that shape. The config `Predicate` in `pipe/filter.rs` intentionally
  ignores its input and advances an internal gate. A vsh name/options check
  must use an input-aware pure pipe (or `and_then`), not that settings enum.
- `gate`’s index wording overstates the library module: `Demand` is a
  `SendPipe` dormancy wrapper with `Out=()` (WAIT). The example implements its
  SHED wrapper locally and demonstrates BALANCE in a local selection loop.
  Vsh has no matching card; do not add a vsh readiness abstraction.
- `chaos`’s index names a reusable `Chaos<Inner>`, but that generic type is
  defined in `examples/chaos/main.rs`; the library module takes an HTTP
  `PipeHandle` and its builder is std-gated. Vsh does not need fault injection;
  if that pattern becomes required, contribute the generic primitive to
  Proxima first.
- `load-balance`’s example implements a local `LoadBalancerPipe`; the reusable
  `Selection` API still fixes `Request<Bytes>`, `UpstreamRef`, and
  `Response<Bytes>`. It is not a generic vsh interpreter-selection primitive.
