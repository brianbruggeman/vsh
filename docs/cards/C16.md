## Design evidence

The existing `CliAction` enum is the action choice. `RunActionPipe` is a
zero-sized orchestrator that composes existing `LifecyclePipe`, `CreateVenvPipe`,
`ShellPipe`, `RemoveVenvPipe`, and `DiscoverVenvsPipe` without adding an action
state struct. `ParseCreateOptionsPipe` is a separate boundary from command
selection and maps flags into the existing derived `CreateOptions`. The
configuration parser returns unconsumed action arguments alongside the
validated `Config`, so shell arguments remain OS strings.

## Reviews

### Code↔card

The six action integration tests cover persistent create, configured enter,
list, dry-run, remove, ephemeral success/nonzero exit cleanup, pre-existing
path refusal, and partial create cleanup. The gate also covers CLI
parsing/configuration; C05 separately exhaustively checks the FSM transition
table. C16 inherits `ShellPipe`'s captured output from C13, so interactive
terminal forwarding is explicitly deferred.

### Tests↔card

Code↔card review passed at 2026-10-14 16:58:15 UTC; tests↔card review passed
at 2026-10-14 16:58:19 UTC. Both confirmed the final source and post-fix gates
match the card. The reviews found that a create failure could remove a
pre-existing environment, PATH resolution could bypass ephemeral cleanup, and
target reservation initially rejected missing parents. Added an unused-path
precondition, atomic final-target reservation with parent creation inside
`CreateVenvPipe`, put PATH resolution inside the cleanup-handled result, and
kept dry-run outside the removal transition.

## Postmortem

Initial review catches were useful: reviews ran against the actual changes and
found lifecycle and test coverage gaps before landing. Keep the two independent
reviews after the final validation run so their evidence matches the committed
tree. Make the `ShellPipe` interaction contract visible in the card; future
interactive-shell work needs an explicit pipe and terminal-backed acceptance
test rather than assuming captured output is interactive.
