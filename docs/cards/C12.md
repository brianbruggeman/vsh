- Discover valid venv paths with a bounded traversal and prune recursion at a

- Resolve stale interpreter and shell paths from explicit search directories;
  try a stale path's basename before generic fallbacks and preserve already

  traversal, interpreter fixture resolution, stale-path fallback, and `.vshrc`

## Design evidence

The three zero-sized pipe types have distinct transformations that callers
compose directly: `PathBuf -> Vec<PathBuf>` for inventory,
`(Config, Vec<PathBuf>) -> Config` for executable fallback, and
`(Config, Vec<PathBuf>) -> Vec<PathBuf>` for `.vshrc` search. Existing Config
holds the chosen venv/interpreter/shell values; caller-supplied path vectors
carry search roots into the library. No pipe reads `HOME`, `PATH`, cwd, or
`WORKON_HOME` implicitly. The traversal uses an explicit stack, canonical-path
visited set, the build-time `MAX_WALK_DEPTH`, and C09's composed observer and
validator. The depth bound applies to candidate paths before they are inspected;
a valid venv is pruned, and output is sorted by full path. Stale executable
basenames are preferred before generic Python/shell names to retain an explicit
configured version when available. `VenvLayout` already exists from C09, so
C12 adds no data wrapper. The three zero-sized types are required to implement
Proxima's `Pipe` for these distinct input/output shapes; no state or logic is
duplicated between them.

## Postmortem

The first review cycle found two issues that code inspection alone missed:
sorting only by basename is not total ordering, and checking a candidate before
its depth bound permits one extra level. Keep a boundary fixture at the exact
limit and one beyond it. When a stale path carries a specific version/name,
search that basename before generic fallback candidates. The card completed in 5 minutes against an 18-minute estimate; future discovery cards should retain these boundary and tie-order fixtures from their first test pass.
