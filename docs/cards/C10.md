## Design evidence

`CreateVenvPipe` is the one zero-sized Proxima implementation type required by
the process operation. Its types are `In=(Config, CreateOptions)`, `Out=Config`,
and `Err=conflaguration::Error`. It uses the existing `Config` and
`CreateOptions` values and the existing C09 layout pipes; it adds no request or
result wrapper. The CLI supplies the interpreter/config; no environment
resolution or PATH search happens in the library operation. Python owns venv
creation semantics via `python -m venv`, so vsh does not duplicate them.

## Reviews

### Code↔card

Initial review at 2026-10-14 16:22:51 UTC found that `working` was used as the
child process cwd instead of being saved as `Config::working_path`, and that a
failed interpreter exit was mislabeled as config validation. Both were
corrected: the returned config stores the startup path, process cwd is left to
the caller, and process exit failure maps to an I/O operation error. Re-review
passed at 16:24:58 UTC.

### Tests↔card

Initial reviews at 16:22:38 and 16:24:57 UTC requested validation error proof,
interpreter override, observable option behavior, and a Windows copy-mode
assertion. The final tests↔card review passed at 2026-10-14 16:25:49 UTC and
confirmed every criterion is asserted. Native Windows execution remains for
the later platform card.

## Postmortem

Postmortem: The first review surfaced an option semantics mismatch: `working`
is the environment's saved startup directory, not the cwd for `python -m venv`.
Preserving the config value and asserting it fixed the behavior. Real process
tests also need observable proof for interpreter selection, non-default flags,
and error types, so an absent interpreter cannot masquerade as pre-effect
validation. This card took 4 minutes against an 18-minute estimate.
