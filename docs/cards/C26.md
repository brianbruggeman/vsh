# C26 — Close 0.8.0 version consistency

## Goal

Make the already-selected 0.8.0 release auditable across manifests, CLI/PyO3
version surfaces, persisted configuration, user-facing install examples, and the
changelog. Avoid changing correct version declarations or legacy fixtures.

## Acceptance

- Add a truthful `0.8.0` section to `CHANGES.rst` using behavior already proven
  by C01–C25 and C29's native installed-wheel gate.
- Replace duplicated CLI help version text with the Cargo package version.
- Verify installed distribution metadata, CLI `--version`, and
  `vsh.__version__` all report the same version.
- `Config::default()`, environment resolution, a missing serde field, and an
  omitted Python `Config` version all default to the crate package version.
- Persist and reload the package version; explicit legacy 0.7.x fixture values
  remain intact.
- Assert CLI help/version, metadata, PyO3 package version, and persisted config
  roundtrip all match the package version.
- Audit Cargo workspace/crate and Python package metadata plus README/guide
  install examples for 0.8.0.
- Run `cargo test --workspace` (nonzero tests), `cargo fmt --all -- --check`,
  `uv run --no-project --with flake8 flake8 tests/test_installed_wheel.py`, and
  the native installed-wheel matrix on Linux/macOS/Windows (4+ tests per job).
- Obtain independent code↔card and tests↔card reviews, write and review a
  postmortem, then promote green coherent commits worktree branch → local
  `main` → `origin/main`.

## Baseline evidence

Cargo workspace version and `pyproject.toml` are already `0.8.0`. PyO3 module
version comes from `CARGO_PKG_VERSION`; CLI `--version` does too, but help text
duplicates `0.8.0`. Installed-wheel tests compare CLI version with distribution
metadata, but do not compare `vsh.__version__`. The config roundtrip test uses a
literal `0.8.0`, and `Config::default()` plus the Python constructor default the
version to an empty string. `README.rst` and `docs/using-vsh.md` contain install
examples for 0.8.0. `CHANGES.rst` has no 0.8.0 entry.

## Postmortem

Manifest and guide versions already agreed on 0.8.0; the drift risks were the
hardcoded CLI help prefix, empty runtime/Python config defaults, and test
literals that could silently age. A shared `Config::default()` seeds the
validated environment builder, serde's missing-field behavior, and omitted
PyO3 constructor argument. Explicit legacy 0.7.x values remain unchanged. The
local wheel gate proves metadata, CLI, and Python API versions agree on Darwin;
native hosted jobs confirmed all three platforms. The macOS runner queued for about 17 minutes. A push-triggered matrix had already started, but a redundant manual dispatch created a duplicate queued run; the manual run was canceled. Next time inspect push-triggered workflows before manually dispatching. The card completed in 27m10s from 20:40:22Z through 21:07:32Z, 12m10s above target. Most of the overrun was the macOS runner queue; a redundant manual dispatch of an already push-triggered workflow added queue pressure and was canceled.
Correction for the next release: audit version boundaries, defaults, and
legacy-file behavior before editing manifests; compare runtime surfaces to
package metadata instead of another copy of the release string.
