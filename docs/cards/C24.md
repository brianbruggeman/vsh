## Validation

The portable runner is `scripts/card_c24_matrix.py`. It builds one wheel
using the current interpreter, checks the wheel tags against its supported
tags, creates a fresh uv environment, installs the wheel and pytest, then runs
the C23 installed-wheel tests through `scripts/card_gate.py`. The local native
macOS run built `vsh-0.8.0-cp39-abi3-macosx_11_0_arm64.whl`, confirmed its tags
intersect the runner's supported tags, then installed that exact wheel in a
UUID-named fresh venv. It confirmed metadata version `0.8.0`, both imports
under that venv's `site-packages`, and that `direct_url.json` points to the
exact built wheel. The gate passed 2/2; log: `target/card-logs/C24-darwin.log`.

## Postmortem

C23's independent review showed that wheel provenance must be checked from
the interpreter that installed the artifact. This card reuses those exact
metadata and path assertions on all three native runners. Initial C24 reviews
also caught an OS-only tag check that ignored CPU architecture, and reusable
wheel/venv paths that could admit stale state. The runner now intersects wheel
tags with `packaging.tags.sys_tags()`, rejects a universal wheel, allocates
UUID-named wheel and venv paths, and checks the installed direct URL against
the just-built wheel. The first local setup attempt used stdlib `ensurepip`
and aborted under uv's Python 3.13.0rc2; the runner now provisions the venv and
dependencies with uv, matching CI. A system-level pip attempt was rejected by
macOS PEP 668, so local validation uses `uv run --no-project --with maturin
--with packaging python scripts/card_c24_matrix.py`.
