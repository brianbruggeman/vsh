# C24 — Native wheel matrix

## Acceptance

- On native Linux, macOS, and Windows runners, build one wheel for that
  platform and reject a wheel whose platform tag does not match the runner.
- Install each wheel into a fresh environment and run the shared C23 tests for
  console metadata/version, console path, Rust API imports, and module paths.
- Require a nonzero test count for each matrix job and inspect all completed
  jobs before promotion.
- Record independent code↔card and tests↔card reviews, postmortem, timestamps,
  and promote only green through worktree → local `main` → `origin/main`.

## Validation

The portable runner is `scripts/card_c24_matrix.py`. It builds one wheel
using the current interpreter, checks the wheel's native platform tag, creates
a fresh uv environment, installs the wheel and pytest, then runs the C23
installed-wheel tests through `scripts/card_gate.py`. The local native macOS
run built `vsh-0.8.0-cp39-abi3-macosx_11_0_arm64.whl`, confirmed metadata
version `0.8.0` and both imports under
`target/c24-venv/lib/python3.13/site-packages`, and passed 2/2 tests. Its gate
log is `target/card-logs/C24-darwin.log`.

## Postmortem

C23's independent review showed that wheel provenance must be checked from
the interpreter that installed the artifact. This card reuses those exact
metadata and path assertions on all three native runners, and also checks
that each built wheel's platform tag matches its runner. The first local
setup attempt used stdlib `ensurepip` and aborted under uv's Python 3.13.0rc2;
the runner now provisions the venv and dependencies with uv, matching the CI
setup. A system-level pip attempt was also rejected by macOS PEP 668, so local
validation uses `uv run --no-project --with maturin python
scripts/card_c24_matrix.py`.
