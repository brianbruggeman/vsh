# C24 — Native wheel matrix

## Acceptance

- On native Linux, macOS, and Windows runners, build one wheel for that
  platform and reject a wheel whose platform tag does not match the runner.
- Install each wheel into a fresh environment and run the shared C23 tests for
  console metadata/version, console path, Rust API imports, and module paths.
- Require a nonzero test count for each matrix job and inspect all completed
  jobs before promotion.
- Record independent code↔card and tests↔card reviews, postmortem, timestamps,
  and promote only green through worktree → local `main` → `origin/main`.

## Validation

using the current interpreter, checks the wheel tags against its supported
tags, creates a fresh uv environment, installs the wheel and pytest, then runs
the C23 installed-wheel tests through `scripts/card_gate.py`. The local native
macOS 15.8 arm64 run on `0861120` built

## Postmortem

C23's independent review showed that wheel provenance must be checked from
the interpreter that installed the artifact. This card reuses those exact
metadata and path assertions on all three native runners. Initial C24 reviews
also caught an OS-only tag check that ignored CPU architecture, and reusable
wheel/venv paths that could admit stale state. The runner now intersects wheel
tags with `packaging.tags.sys_tags()`, rejects a universal wheel, allocates
UUID-named wheel and venv paths, and checks the installed direct URL against
the just-built wheel. The first local setup attempt used stdlib `ensurepip`
and aborted under uv's Python 3.13.0rc2; the runner now provisions the venv and
dependencies with uv, matching CI. A system-level pip attempt was rejected by
macOS PEP 668, so local validation uses `uv run --no-project --with maturin
--with packaging python scripts/card_c24_matrix.py`.

The first hosted matrix used `macos-latest`, now mapped to macOS 26. Its job
remained queued without a runner assignment for about 14 minutes while Linux
and Windows completed; it was canceled after confirming it had no runner.
Changing the matrix to `macos-15` matched the local 15.8 arm64 host, but that
job also waited 10m02s for runner assignment (18:38:22–18:48:24 UTC). It then
built and passed in under two minutes. C24 took 33 minutes against its 18-minute
estimate and missed the 20-minute target because of hosted runner allocation;
there was no code or test failure. For future cards, dispatch external gates as
soon as their inputs stabilize, track queue time separately from execution,
include observed runner allocation delays in the ETA, and keep native workflow
triggers scoped to wheel inputs so documentation-only cards do not repeat the
external wait. The global `coherent-cards` skill now requires timestamped
progress, separate reviews, a reviewed postmortem, and a truthful timebox-miss
correction. Final filter review caught that the wheel packages `LICENSE` and
does not embed `README.rst`; the workflow now triggers on the actual license
input and avoids a README-only run. A second review caught pytest's imported
`conftest.py`, decorators, and fixtures; changes to those files also trigger the
matrix.
