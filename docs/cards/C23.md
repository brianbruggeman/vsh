## Validation

Built `/private/tmp/vsh-c23-wheel/vsh-0.8.0-cp39-abi3-macosx_11_0_arm64.whl`
with maturin and installed it with pytest into the isolated environment at
`/private/tmp/vsh-c23-venv`. The build and install commands were:

```sh
uv run --no-project --with 'maturin>=1.7,<2' maturin build --manifest-path crates/vsh-py/Cargo.toml --out /private/tmp/vsh-c23-wheel --interpreter python3.13
uv venv /private/tmp/vsh-c23-venv --python 3.13
uv pip install --python /private/tmp/vsh-c23-venv/bin/python /private/tmp/vsh-c23-wheel/*.whl pytest
```

Ran the gate from `/private/tmp`, with no source checkout on the import path.
`/private/tmp/vsh-card-c23/target/card-logs/C23-python-final.log` records 2
passed, 0 failed. The installed console executable
`/private/tmp/vsh-c23-venv/bin/vsh` (whose shebang targets that venv) reported
`0.8.0`, matching metadata queried by the isolated Python 3.13 interpreter.
Both `vsh` and `vsh._vsh` resolved from
`/private/tmp/vsh-c23-venv/lib/python3.13/site-packages`; the test confirmed
the Rust CLI callable and library types exist.
Installed distribution metadata records the expected console entry point
`vsh = vsh:main` and wheel source
`/private/tmp/vsh-c23-wheel/vsh-0.8.0-cp39-abi3-macosx_11_0_arm64.whl`.

`cargo test -p vsh-cli` passed 19 tests (11 library, 6 actions, 1 config,
1 telemetry); `cargo check -p vsh-py`, `cargo fmt --all -- --check`, and
`git diff --check` passed.

## Postmortem

The first version of the gate reported two passes but could have accepted a
source-tree CLI and an unrelated/global wheel because its version and import
path expectations came from external inputs. Independent review exposed those
provenance gaps. The final gate derives expected version, scripts directory,
and site-packages from the isolated interpreter itself, then prints the
installed paths. For C24, each native matrix job should assert its wheel's
platform tag and executable/import provenance within that job's environment.
