## Design evidence

`VenvLayout` is justified as the boundary value between filesystem observation
and a pure rule. It preserves the individual facts, supports callers that need
to explain an invalid layout, and lets the validator run with no filesystem
access. The two zero-sized pipe types implement distinct operations:
`PathBuf -> VenvLayout` and `VenvLayout -> bool`. Proxima's `and_then` composes
them without a custom orchestration type. Both have `Err=Infallible`; OS I/O
errors become absent facts, which means an unreadable/missing required path
invalidates the layout.
